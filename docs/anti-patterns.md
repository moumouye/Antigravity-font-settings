# ③ 否决与避坑档案 (Anti-Patterns & Dead Ends)

本文档记录本项目演进历程中被**实测证明失败并彻底否决的技术方案与缺陷根因档案**。
严禁将以下已否决方案重新引入代码库。

---

## 避坑总览表

| 否决方案编号 | 方案名称 | 致命缺陷现象 | 真实技术根因 | 唯一合法解决方案 |
| :--- | :--- | :--- | :--- | :--- |
| **AP-01** | **CSS 文件中保留 JS 字符串双反斜杠转义** | 正文及侧栏字号调节完全失效，样式未生效 | 模块拆分后将原生 CSS 文件中的选择器写作 `w-\\[1px\\]`；CSS 解析器无法识别双反斜杠序列，判定为语法错误并直接丢弃整条规则 | 原生 CSS 文件中严格使用单反斜杠转义 `w-\[1px\]`；测试套件中建立 CSS 规则解析完整性机器断言 |
| **AP-02** | **单次 `Runtime.evaluate` 裸注入** | 宿主升级、窗口刷新或重载后设置面板丢失，字号回退默认 | Electron 页面刷新或导航时，原 JavaScript 执行上下文与 DOM 彻底销毁，单次求值注入的脚本与 CDP RPC 绑定全部丢失 | 开启 `Page.enable` 并结合 `Page.addScriptToEvaluateOnNewDocument` 注入守卫；Sidecar 监听导航事件执行自愈重绑 |
| **AP-03** | **无隔离的通用标签选择器声明** | 设置弹窗变形、快捷键面板文字错位、标题异常放大 | `h1`、`table`、`p` 等字号乘数规则未加限定，污染宿主原生的设置对话框与模态窗口 | 强制添加 `:not([role="dialog"] *):not(.settings-modal-container *)` 负向伪类，设置侧栏锁定原生 14px |
| **AP-04** | **独立代码字号滑块与自定义字体族输入** | 排版比例失调、不同平台字体缺失、设置面板冗长拥挤 | 独立字号导致正文与代码行内比例脱节；自定义字体族受限于各操作系统安装状态易发回退变形 | 代码字号与正文执行 1:1 严格绑定（`--agy-font-code: var(--agy-font-main)`）；排版全面采用系统原生字体栈 |

## 深度剖析 (Why it failed)

### AP-01：为什么原生 CSS 文件中绝对不能出现 `\\[` 转义？
* **事故复盘**：在工程早期，样式以 JavaScript 模板字符串（`const style = \`...\``）形式内嵌于单文件中，为了向生成的字符串输出单个反斜杠，开发者编写了双反斜杠 `\\[`。解耦拆分为独立 `styles.css` 原生样式表后，若未将转义还原，浏览器在解析 `.css` 文件时，会将 `\\[` 视为两个连续反斜杠加括号，导致整个复合选择器被判定为非法。
* **物理防线**：任何针对样式表的修改，必须在测试套件中通过 `el.sheet.cssRules` 读取浏览器真实解析后的规则总数，必须保证所有关键规则合法入表。

### AP-02：为什么仅靠 `Runtime.evaluate` 无法维持插件生命周期？
* **事故复盘**：早期直接向活跃页面执行单次 `Runtime.evaluate`。当用户在宿主中按下快捷键重载界面（Cmd/Ctrl+R）或 Antigravity 客户端自动升级后，窗口重新加载新文档，之前注入的 DOM 元素与全局变量（`window.__agyFontSavePrefs`）被整页清空，插件彻底失效。
* **物理防线**：必须在建立 CDP 会话时调用 `Page.addScriptToEvaluateOnNewDocument`，将包装好的自执行闭包注册为“新文档加载前必须执行的脚本”，同时在 CDP 客户端中监听 `Page.loadEventFired` 与 `Page.frameNavigated` 事件，自动重新注册 RPC 绑定。

### AP-03：为什么 Markdown 规则必须排斥弹窗容器？
* **事故复盘**：为了提升对话区 Markdown 阅读体验，系统为 `h1` 设置了 `1.45em`、`table` 设置了 `1:1` 等比。然而设置弹窗、指令选择面板同样由 HTML 构成，缺少作用域约束时，设置面板内的小标题与表格被误伤放大，破坏了官方原生视觉节奏。
* **物理防线**：所有针对 Markdown 排版的规则必须携带双重隔离选择器：`:not([role="dialog"] *):not(.settings-modal-container *)`，且设置弹窗左侧导航文字强制内联 `font-size: 14px !important`。

### AP-04：为什么必须废除独立代码字号滑块并收敛字体族？
* **事故复盘**：早期版本为代码块（Code Block）与字体族设置了单独的配置项。实测发现：当正文字号调大时，用户期望代码块与内联代码按相同比例缩放；若两者割裂，行内引用与上下文字距极不协调。此外，自定义字体族在 macOS 与 Windows 之间存在字体名称不一致、字符缺失等不可控情况。
* **物理防线**：彻底移除代码字号配置与字体族输入，代码字号恒等于正文字号，字体继承宿主原生无衬线与等宽字体栈，保持跨端绝对一致性。
